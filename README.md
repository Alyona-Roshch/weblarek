# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две ключевые сущности, описывающие бизнес-данные интернет-магазина: товар в каталоге и покупатель, оформляющий заказ.

#### Интерфейс IProduct

Описывает структуру данных отдельного товара. Используется для хранения информации о карточках в каталоге, модальных окнах и корзине.

```typescript
interface IProduct {
  id: string; // Уникальный идентификатор товара
  description: string; // Полное текстовое описание товара
  image: string; // URL-ссылка на картинку товара
  title: string; // Название товара
  category: string; // Категория товара
  price: number | null; // Стоимость товара в условных единицах (null для бесценных товаров)
}
```

#### Интерфейс IBuyer

Описывает структуру персональных данных покупателя, необходимых для успешного формирования и валидации заказа.

```typescript
interface IBuyer {
  payment: TPayment; // Выбранный способ оплаты
  email: string; // Электронная почта покупателя
  phone: string; // Контактный телефон
  address: string; // Адрес доставки заказа
}
```

## Модели данных

Модели данных (классы-модели) изолированно хранят внутреннее состояние приложения, отвечают за хранение и работу с данными, а также генерируют события через `EventEmitter` при их изменении.

### Класс ProductModel (Каталог товаров)

Класс отвечает за хранение общего списка товаров, полученных с сервера, а также за отслеживание товара, который пользователь выбрал для детального просмотра в модальном окне.

Конструктор:
`constructor(events: IEvents)` — принимает экземпляр брокера событий для уведомления презентера об изменениях в каталоге.

Поля класса:
`private items: IProduct[]` — массив всех доступных для покупки товаров.
`private preview: IProduct | null` — товар, выбранный в данный момент для подробного отображения в модальном окне (или `null`, если окно закрыто).

Методы класса:
`setItems(items: IProduct[]): void` — сохраняет массив товаров в модель и инициирует событие изменения каталога.
`getItems(): IProduct[]` — возвращает полный массив товаров, хранящихся в модели.
`getProduct(id: string): IProduct | undefined` — ищет и возвращает объект товара из массива по его уникальному идентификатору `id`.
`setPreview(item: IProduct | null): void` — сохраняет товар для подробного отображения и генерирует событие открытия карточки.
`getPreview(): IProduct | null` — возвращает товар, выбранный для подробного отображения.

### Класс BasketModel (Корзина)

Класс отвечает за хранение товаров, которые покупатель выбрал для покупки, а также за расчет итоговых показателей (стоимость, количество).

Конструктор:
`constructor(events: IEvents)` — принимает экземпляр брокера событий для отправки уведомлений об обновлении содержимого корзины.

Поля класса:
`private items: IProduct[]` — массив товаров, добавленных пользователем в корзину.

Методы класса:
`getItems(): IProduct[]` — возвращает массив всех товаров, находящихся в корзине в данный момент.
`add(item: IProduct): void` — принимает объект товара и добавляет его в массив корзины.
`remove(id: string): void` — удаляет товар из массива корзины по его идентификатору `id`.
`clear(): void` — полностью очищает массив корзины.
`getTotalPrice(): number` — рассчитывает и возвращает суммарную стоимость всех товаров в корзине.
`getQuantity(): number` — возвращает общее количество товаров в корзине (длину массива).
`hasItem(id: string): boolean` — проверяет, добавлен ли уже товар с указанным `id` в корзину. Возвращает `true`, если товар есть, и `false`, если отсутствует.

### Класс BuyerModel (Данные покупателя)

Класс отвечает за хранение, поэтапное обновление и валидацию контактных данных и информации о доставке, вводимых пользователем при оформлении заказа.

Конструктор:
`constructor(events: IEvents)` — принимает экземпляр брокера событий для уведомления системы о результатах валидации полей формы.

Поля класса:
`private payment: string` — вид оплаты.
`private address: string` — адрес доставки.
`private email: string` — адрес электронной почты.
`private phone: string` — контактный телефон.

Методы класса:
`setField(field: keyof IBuyer, value: string): void` — сохранение данных в модели. Метод обновляет значение только одного конкретного поля, полученного в параметре, не затирая при этом значения других полей, которые уже хранятся в классе. После сохранения автоматически вызывает метод валидации.
`getBuyerData(): IBuyer` — получение всех данных покупателя в виде единого объекта.
`clear(): void` — очистка данных покупателя (сброс всех полей класса в начальное пустое состояние).
`validate(): boolean` — валидация данных. Проверяет каждое поле класса на заполненность (поле считается валидным, если оно не пустое). Метод формирует объект ошибок, где ключами выступают названия полей с ошибками, а значениями — текст ошибки (если поле заполнено, свойство отсутствует). Объект передается в брокер событий. Метод возвращает `true`, если все поля валидны, и `false`, если обнаружена хотя бы одна ошибка.

_Пример генерируемого объекта ошибок при неуспешной валидации:_

```json
{
  "payment": "Не выбран вид оплаты",
  "email": "Укажите емэйл"
}
```

## Слой коммуникации

Слой коммуникации отвечает за непосредственное сетевое взаимодействие приложения с API-сервером интернет-магазина. Он изолирует детали выполнения HTTP-запросов от основной логики презентера.

### Класс LarekApi

Класс является представителем коммуникационного слоя. Он использует композицию, оборачивая базовый класс `Api`, и предоставляет строго типизированные специализированные методы для получения каталога товаров и отправки сформированных заказов на сервер.

Конструктор:
`constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi`, предоставляющий базовые методы отправки запросов (`get` и `post`).

Поля класса:
`private _api: IApi` — экземпляр базового коммуникационного класса для выполнения HTTP-запросов.

Методы класса:
`getProductList(): Promise<IProduct[]>` — выполняет GET-запрос на эндпоинт `/product/`. Возвращает промис с массивом объектов товаров, извлечённых из ответа сервера.
`createOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order/`, передавая в теле запроса структурированные данные о покупателе и выбранных товарах. Возвращает промис с объектом-подтверждением покупки, содержащим уникальный id заказа и итоговую списанную сумму.

## Слой представления (View)

Классы слоя View отвечают исключительно за отображение данных в DOM-дереве и перехват пользовательских действий (кликов, ввода текста, отправки форм). Они не хранят состояние и не содержат бизнес-логики: при любом действии пользователя компонент генерирует событие через брокер `EventEmitter` (или вызывает переданный в конструктор колбэк), а изменение отображения происходит через сеттеры и метод `render()`.

### Класс Page (Главная страница)

Отвечает за отображение основных элементов главной страницы: контейнера с каталогом товаров, счётчика товаров на иконке корзины в шапке и блокировку прокрутки страницы при открытии модального окна.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент страницы (`body.page`) и экземпляр брокера событий. Находит элементы `.header__basket-counter`, `.gallery`, `.page__wrapper` и `.header__basket`, вешает слушатель клика на иконку корзины.

Поля класса:
- `protected _counter: HTMLElement` — элемент счётчика товаров в шапке;
- `protected _catalog: HTMLElement` — контейнер для вывода карточек каталога;
- `protected _wrapper: HTMLElement` — обёртка страницы для блокировки скролла;
- `protected _basket: HTMLElement` — кнопка открытия корзины.

Сеттеры: 
- `set counter(value: number)` — устанавливает текстовое значение счётчика товаров в корзине;
- `set catalog(items: HTMLElement[])` — заменяет содержимое контейнера каталога переданным массивом карточек;
- `set locked(value: boolean)` — добавляет или удаляет класс `page__wrapper_locked` для блокировки прокрутки при открытом модальном окне.

Генерируемые события:
- `basket:open` — при клике пользователя на иконку корзины в шапке.

### Класс Modal (Модальное окно)

Универсальный компонент модального окна. Отвечает за открытие, закрытие (по кнопке крестика или клику по оверлею) и подмену отображаемого контента. Не имеет дочерних классов.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает контейнер модального окна (`#modal-container`) и брокер событий. Находит кнопку закрытия `.modal__close` и контейнер контента `.modal__content`, устанавливает обработчики закрытия.

Поля класса:
- `protected _closeButton: HTMLButtonElement` — кнопка закрытия модального окна;
- `protected _content: HTMLElement` — внутренний контейнер для вставки разметки;
- `protected events: IEvents` — брокер событий.

Сеттеры и методы: 
- `set content(value: HTMLElement | null)` — заменяет содержимое внутри `.modal__content`;
- `open(): void` — открывает модальное окно (добавляет класс `modal_active`) и генерирует событие `modal:open`;
- `close(): void` — закрывает модальное окно (удаляет класс `modal_active`), очищает контент и генерирует событие `modal:close`;
- `render(data: IModalData): HTMLElement` — устанавливает контент и автоматически открывает модальное окно.

Генерируемые события: 
- `modal:open` — при открытии окна;
- `modal:close` — при закрытии окна.

### Класс Form (Базовый класс формы)

Родительский компонент для всех форм приложения. Управляет состоянием кнопки отправки (активна/заблокирована), отображением текста ошибок валидации и перехватом пользовательского ввода.

Конструктор:
`constructor(protected container: HTMLFormElement, protected events: IEvents)` — принимает DOM-элемент формы (`<form>`) и брокер событий. Находит кнопку отправки `button[type=submit]` и блок ошибок `.form__errors`, навешивает слушатели событий `input` и `submit`.

Поля класса:  
- `protected _submit: HTMLButtonElement` — кнопка отправки формы;
- `protected _errors: HTMLElement` — элемент для вывода сообщений об ошибках.

Сеттеры и методы:  
- `set valid(value: boolean)` — включает или отключает (`disabled`) кнопку отправки формы;
- `set errors(value: string)` — выводит текст ошибки в блок `.form__errors`;
- `protected onInputChange(field: keyof T, value: string): void` — генерирует событие изменения конкретного поля формы;
- `render(state: Partial<T> & IFormState): HTMLFormElement` — обновляет валидность, ошибки и значения полей формы.

Генерируемые события:
- `${formName}.${field}:change` — при вводе данных в любое поле формы (передаёт `{ field, value }`);
- `${formName}:submit` — при отправке формы.

### Семейство классов карточек товара

#### Класс Card (Базовый класс карточки)

Родительский класс для всех вариантов отображения товара. Содержит только общую для всех карточек логику отрисовки названия и цены.

Конструктор:  
`constructor(container: HTMLElement)` — принимает корневой элемент карточки. Находит элементы `.card__title` и `.card__price`.

Поля класса:
- `protected _title: HTMLElement` — элемент заголовка товара;
- `protected _price: HTMLElement` — элемент отображения цены.

Сеттеры:
- `set title(value: string)` — устанавливает название товара;
- `set price(value: number | null)` — форматирует и выводит цену (`"${value} синапсов"` или `"Бесценно"` при `null`).

#### Класс CardCatalog (Карточка в каталоге)

Наследник `Card`. Отвечает за отображение компактной карточки товара на витрине главной страницы (`#card-catalog`).

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardActions)` — вызывает родительский конструктор, находит элементы `.card__image` и `.card__category`, устанавливает слушатель клика на контейнер карточки.

Дополнительные поля и сеттеры:
- `protected _image: HTMLImageElement` — изображение товара;
- `protected _category: HTMLElement` — элемент плашки категории;
- `set category(value: string)` — устанавливает текст категории и применяет соответствующий CSS-модификатор из `categoryMap`;
- `set image(value: ICardImage)` — устанавливает изображение и альтернативный текст (`{ src, alt }`) через базовый метод `setImage`.

#### Класс CardPreview (Детальная карточка товара)

Наследник `Card`. Отображается внутри модального окна (`#card-preview`). Дополняет базовую карточку изображением, категорией, подробным описанием и кнопкой действия.

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardActions)` — вызывает родительский конструктор, находит `.card__image`, `.card__category`, `.card__text` и `.card__button`, навешивает обработчик клика на кнопку.

## Слой Презентера (Presenter)

Логика слоя Презентера реализована в файле `src/main.ts` в виде набора обработчиков событий брокера `EventEmitter`.

**Основная суть Презентера:**
- Связывает изолированные слои **Model** и **View**, не позволяя им обращаться друг к другу напрямую.
- Подписывается на события пользовательских действий в интерфейсе (клики, ввод текста, отправка форм) и вызывает соответствующие методы моделей (`ProductModel`, `BasketModel`, `BuyerModel`) или сетевого слоя (`LarekApi`).
- Подписывается на события изменения состояния моделей, подготавливает данные в нужном формате и обновляет отображение через сеттеры и методы `render()` компонентов View.

### События приложения

Взаимодействие между слоями MVP осуществляется через брокер `EventEmitter`:

**События моделей данных (Model ➔ Presenter):**
- `items:changed` — обновился массив товаров в `ProductModel` (перерисовка карточек каталога на главной странице).
- `preview:changed` — в `ProductModel` выбран товар для детального просмотра (открытие модального окна с компонентом `CardPreview`).
- `basket:changed` — изменился состав товаров в `BasketModel` (обновление счётчика товаров на `Page` и перерисовка списка в `Basket`).
- `buyer:changed` — изменились или очистились данные покупателя в `BuyerModel` (обновление значений полей, сообщений об ошибках и активности кнопок в формах `OrderForm` и `ContactsForm`).

**События пользовательских действий (View ➔ Presenter):**
- `product:select` — клик по карточке товара в каталоге `CardCatalog` (передача выбранного товара в `ProductModel`).
- `preview:toggle` — клик по кнопке «Купить» / «Удалить из корзины» в `CardPreview` (добавление или удаление товара в `BasketModel` и закрытие модального окна).
- `basket:open` — клик по иконке корзины в шапке `Page` (открытие модального окна с компонентом `Basket`).
- `basket:remove` — клик по кнопке удаления позиции в `CardBasket` (удаление товара из `BasketModel`).
- `order:open` — клик по кнопке «Оформить» в `Basket` (открытие первого шага оформления заказа `OrderForm`).
- `order.<field>:change` / `contacts.<field>:change` — изменение способа оплаты или ввод текста в полях форм (сохранение значения в `BuyerModel`).
- `order:submit` — отправка первой формы заказа `OrderForm` (переход ко второму шагу `ContactsForm`).
- `contacts:submit` — отправка второй формы заказа `ContactsForm` (отправка заказа на сервер через `LarekApi`, очистка корзины и данных покупателя, открытие окна `Success`).
- `success:close` — клик по кнопке «За новыми покупками!» в окне `Success` (закрытие модального окна).
- `modal:open` / `modal:close` — открытие и закрытие модального окна `Modal` (блокировка и разблокировка прокрутки страницы через `Page`).
